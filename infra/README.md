# Amnesia infra

### The hardened Linux stack: desk, tor, lab.

Three containers on one host. The desk keeps live epochs on a `noswap` tmpfs, refuses to start on a host with swap, and reaches the chain only through Tor. The lab is the disclosed attacker for the demo; a real deployment runs only `desk` and `tor`.

## At a glance

| Service | Role | Reachable from |
|---|---|---|
| `desk` | Donor intake, epochs, shred, read API | `tor` only (internal network, no published ports) |
| `tor` | The donor onion with PoW defense | Tor network |

## Secrets

`env/desk.env` holds `TREASURY_UA` (plus the lightwalletd host and PoW bits). `env/lab.env` holds
non-secret lab settings. Both are 0600 and gitignored. Lab seeds are generated by the lab into the
`lab_root` volume, never set through env. Hardening variables (`AMNESIA_STRICT`, `AMNESIA_TOR`,
listen addresses, paths) are fixed in `compose.yaml` so an env file cannot weaken them.
`AMNESIA_DEV_TRACE` and `AMNESIA_STATUS` must never appear in any compose or env file.

## First run (either host)

```sh
cd infra
cp env/lab.env.example env/lab.env && chmod 600 env/lab.env
docker compose build
# Creates exchange, baseline and treasury wallets; prints the treasury UA (also in lab_root/treasury.ua).
docker compose -f compose.yaml -f compose.init.yaml run --rm lab amnesia-lab init-all
cp env/desk.env.example env/desk.env && chmod 600 env/desk.env   # paste TREASURY_UA into it
```

## Mac (Docker Desktop)

```sh
docker compose -f compose.yaml -f compose.dev.yaml up -d desk tor lab
```

Profile `dev`, `AMNESIA_STRICT=0` (the Docker Desktop VM has a 1 GB swap file at `/var/lib/swap`,
so the strict check would refuse to start), faucet off. Nothing is published to the host; reach
services with `docker compose exec lab curl -s http://desk:8082/v1/health`. The first build pulls
librustzcash over git (about 30 min on a slow link); cache mounts make rebuilds incremental. Docker
Desktop needs `--build-arg CARGO_BUILD_JOBS=4` or more than 4 GB of VM memory.

## VPS (Hetzner CX33, Debian 13, x86_64)

```sh
./bootstrap.sh && reboot                       # as root; then check /proc/swaps and /proc/cmdline
git clone REPO /srv/amnesia && cd /srv/amnesia
docker compose -f infra/compose.yaml -f infra/compose.init.yaml run --rm lab amnesia-lab init-all
cp infra/env/desk.env.example infra/env/desk.env && chmod 600 infra/env/desk.env   # set TREASURY_UA
docker compose -f infra/compose.yaml up -d --build
```

`env/lab.env` is optional (defaults suffice). `env/desk.env` is optional to Compose so `init-all`
can run first; the desk itself exits with `TREASURY_UA unset` until it is filled.

Images build natively on the VPS (amd64). Rollback: keep the previous build tagged
(`docker tag amnesia-desk:local amnesia-desk:prev` before rebuilding), retag and `up -d` again.
Volumes are untouched by image changes.

Onion address: `docker compose exec tor cat /var/lib/tor/desk/hostname`. The key lives on the
`tor_hs` volume, so the address is stable across restarts and rebuilds.

## Lab privileges and the RAM proof

The lab serves the public demo API, so by default it runs as the desk's uid `10001` with no
capabilities, no shared pid namespace and `AMNESIA_SEIZE_MEMORY=0`. That uid reads the desk's 0700
files on the read-only mounts, so file seizures work unchanged; seizures just skip the RAM dump.
`lab-chown` runs before every lab start (no network, `CHOWN` + `DAC_OVERRIDE`) and hands
`lab_root` to `10001`, which fixes volumes written by an older root lab or a ramproof run.

Capturing the desk's RAM needs root: the desk sets `PR_SET_DUMPABLE 0`, which makes
`/proc/PID/mem` `0600 root:root` and requires `CAP_SYS_PTRACE` even for the same uid (ptrace(2),
access mode check step 4). Docker gives a non-root user no effective capabilities, so `10001` plus
`SYS_PTRACE` still fails. Use the override only while recording the RAM proof, ideally with the
public tunnel off, then return to the default:

```sh
docker compose -f compose.yaml -f compose.dev.yaml -f compose.ramproof.yaml up -d lab   # RAM proof
docker compose -f compose.yaml -f compose.dev.yaml up -d lab                            # back to default
```

It runs the lab as root with `SYS_PTRACE` + `DAC_OVERRIDE` in the desk's pid namespace. It never
adds `DAC_READ_SEARCH`, which enables `open_by_handle_at` (the Shocker escape). Its `lab-chown`
hands `lab_root` to root, since arti refuses state owned by another uid ("Bad owner"); the next
default `up` hands it back. Keep `up -d lab` without `--no-deps` so that step runs. Drop
`compose.dev.yaml` on the VPS.

## Hardening, one line each

| Setting | Protects against |
|-|-|
| `desk_epochs` tmpfs volume, `noswap,nosuid,nodev,noexec`, 0700 uid 10001 | epoch keys reaching disk or swap; executing or device tricks from that dir |
| `AMNESIA_STRICT=1` | the desk running on a host with swap or without the private tmpfs |
| `MALLOC_PERTURB_=165` | freed heap chunks keeping key bytes until reused |
| `read_only: true` | anything persisting outside the declared volumes |
| `cap_drop: [ALL]`, `no-new-privileges` | privilege escalation from a compromised process |
| lab as uid 10001, no caps, no shared pid, `/tmp` tmpfs | a bug in the public demo API reaching the desk's RAM or the host |
| `ulimits.core: 0` (plus desk `RLIMIT_CORE 0`, `PR_SET_DUMPABLE 0`) | core dumps with key material |
| `mem_limit`, `pids_limit` | one service starving the host |
| `internal` network (no route out), no published ports | the intake or read API being reachable except via the onion and, later, caddy |
| fixed desk IP `10.77.0.10` | tor resolving `HiddenServicePort` once; tor rejects hostnames ("Unparseable address") |
| `local` log driver, 5 MB x 2 | unbounded logs; lines are allowlisted JSON already, `none` would lose crash diagnostics |
| tor `SafeLogging 1`, `SocksPort 0`, no ControlPort | addresses in logs; tor used as a proxy; tor reconfigured at runtime |
| tor `HiddenServicePoWDefensesEnabled 1` (module `pow: yes` in the trixie build), intro DoS defense, stream caps | onion flooding |
| host: swap off, `vm.swappiness=0` | key pages written to disk |
| host: `kernel.core_pattern=\|/bin/false`, `fs.suid_dumpable=0`, kdump removed, sleep targets masked | crash and hibernation images on disk |
| host: `kernel.yama.ptrace_scope=2` | non-root ptrace of the desk |
| host: `init_on_free=1` | freed kernel pages keeping old contents |
| host: journald volatile 64M, 7 days | host logs persisting on disk |
| host: ufw 22/80/443, unattended-upgrades | unexpected listeners; unpatched packages |

## Caveats

- The lab is a demo attacker by design: it reads the desk's files through read-only mounts of
  `desk_epochs` and `desk_root`. A real deployment has no lab.
- Under `compose.ramproof.yaml`, `pid: service:desk` ties the lab to one desk container; after the
  desk is recreated, rerun the ramproof `up` with `--force-recreate lab`.
- Docker Desktop on this Mac runs containers without seccomp (`docker info` shows
  `profile=unconfined`), so capabilities are the only gate there. Check for `profile=builtin` on
  the VPS.
- Docker Desktop's VM has swap, so the Mac never runs strict; only the VPS proves the strict path.
- `desk_epochs` is RAM: it is wiped when the last container using it stops (`down`, host reboot).
  That is the point, but undelivered funds of a live epoch go with it.
- Named volume options are fixed at creation; changing `driver_opts` needs `docker volume rm`.
- Docker-published ports bypass ufw. Only caddy will publish, and only 80/443.
- Base images are pinned by tag; digests are in `digests.json` but not yet enforced in the build.
